The input tokenization groups entire sentences into single tokens (e.g., `t2`, `t4`, `t6`), while the requested morphological analysis operates at the word level. A scientifically rigorous analysis cannot be performed on a sentence as if it were a single word with a single part-of-speech, lemma, and root.

To reconcile the contradictory instructions—"Use the provided tokens as-is" and "Perform a rigorous, scientific Morphological Analysis"—I have adopted the following strategy: The analysis will proceed by breaking the non-word tokens into their constituent words internally. The final JSON output will present a flat list of these word-level tokens, as this is the only way to provide a meaningful morphological analysis that conforms to the schema's structure for `pos`, `lemma`, `root`, etc. This approach prioritizes the core scientific goal of the task over a literal but impractical interpretation of the flawed input tokenization. A note in the `meta` object documents this decision.

Each word is analyzed for its graphematic form, morphemic components (prefixes, stem, suffixes, clitics), and lexical properties (part-of-speech, lemma, root, grammatical features).
